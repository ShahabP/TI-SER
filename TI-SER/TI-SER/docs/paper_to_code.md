## Places where the code and the manuscript text differ

The repository code is a **behaviour-preserving split** of the supplied `TI-SER.py` (every function is
AST-identical to the original). I did not edit the methodology to match the prose. The following
differences exist between that code and the manuscript text, so you should decide which side to change
before submission:

1. **Phase loss (Eq. 32 vs. implementation).** The paper defines phase summaries μ, Δ, Σ on the VA
   trajectory z over build-up `[onset, peak]`, peak `[peak±δ]`, recovery `[peak, recovery]`, with weights
   ωφ, βφ, γφ. The code computes, on the **intensity curve** I(t), a mean-intensity term, a mean
   first-difference (slope, weight `PHASE_SLOPE_WEIGHT=0.5`) and mean second-difference (curvature,
   weight `PHASE_CURVATURE_WEIGHT=0.1`) term over three *non-overlapping* regions
   (`τ < peak−δ`, `|τ−peak| ≤ δ`, `τ > peak+δ`, δ = `PHASE_WINDOW = 0.10`), averaged over terms. There is
   no onset/recovery threshold ε in the loss, and neither ωφ/βφ/γφ nor δ=0.10 is stated in the paper.
2. **Dimensional loss normalisation (Eq. 26).** Paper: squared ℓ2 norm (sum over v, a). Code:
   `reduce_mean` over the two VA dimensions (a factor of ½).
3. **Trajectory descriptors (Eqs. 6–13, RT/PA/RS/AUI).** Defined in the paper but not computed anywhere in
   the code; only the reference-intensity peak is used inside the phase loss.
4. **"No early stopping" (Section 7, Appendix A).** The training loop trains for the fixed epoch budget but
   then **restores the weights from the epoch with the best validation accuracy** before testing
   (`training.train_one`). That is validation-based checkpoint selection and should be stated.
5. **Weight decay for PsyTransformer (Table 6, L2 = 1e-4).** In the code, L2 regularisation is applied to all
   PsyCNN conv/dense kernels, but in PsyTransformer only to the two classifier Dense layers (not to the
   input projection, attention or FFN).
6. **Algorithm 2** shows plain gradient descent `θ ← θ − η∇L`; the code uses Adam (as Table 6 says).
7. **Positional encoding.** Paper says *learned* positional embeddings (matches the `Embedding` layer); a code
   comment calls it "Fixed". Behaviour is learned embeddings.
8. **Multi-seed Transformer.** The paper reports Transformer within/combined results as single-run summary
   estimates, whereas this runner executes every scenario for all configured seeds.

The paper's reported numbers cannot be regenerated byte-for-byte: the runner generates fresh metrics from
the data it finds and never copies old values (see the docstring in `legacy/TI-SER_original_colab_export.py`).
