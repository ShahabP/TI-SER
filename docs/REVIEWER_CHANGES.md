# Code ↔ review reconciliation (second-round report)

Every item of the second-round review is mapped to the change that addresses it and to
the artefact that lets a reviewer verify it. All results must be regenerated with this
pipeline (`PIPELINE_VERSION = 2.0.0`); runs without that tag are treated as historical and
are listed in `results/summary/excluded_runs.txt` by the aggregator.

## Major issue 1 – protocol vs. code mismatch

| Reviewer finding | What was wrong | Fix | Verify |
|---|---|---|---|
| SpecAugment attached to a dataset shared by train/val/test | `SERDataset(transform=SpecAugment())` was passed to `build_splits`, so `Subset`s of the same object augmented val/test too | `SERDataset` no longer accepts a transform. Each split gets its own `IndexedDataset(base, idx, transform)`; train = `Compose([normalise, SpecAugment])`, val/test = `normalise` only. `combined` previously materialised augmented samples once via `_ListDataset`; it now uses index views | `tests/test_no_leakage.py` |
| Random permutation instead of stratification | `build_splits` used `RandomState.permutation` | `src/data/splits.py::stratified_split` (per class, per corpus in `combined`); optional `split_mode: speaker_disjoint` | `tests/test_splits_and_stats.py` |
| Training-only normalisation not reproduced | no normalisation existed in the scripts (`FeatureNormalizer` was never used) | `compute_train_stats` over the training split only; statistics fingerprint stored in every record | `tests/test_no_leakage.py`, `run_record.json → normalization` |
| Leave-corpus-out ignored `lambda_ce`/`lambda_focal`, had no normalisation or augmentation | separate script with its own, inconsistent set-up | now goes through the same `run_experiment`; source-train statistics are applied to the target | `run_record.json` |
| Other bugs found | `parse_tess` used a loose `endswith`; `classification_report` crashed when a class was absent (e.g. CREMA-D has no *surprise*); ablation used 15 epochs / 3 warm-up vs 20 / 5 in main runs | exact last-token parsing; fixed label set; ablations inherit the main config | – |

## Major issue 2 – run-level records
Each run writes `results/<group>/<run_id>/`:
`run_record.json` (seed, resolved config + hash, effective loss weights, split & normalisation
fingerprints, best epoch, parameters, test metrics, environment/git commit),
`test_predictions.csv`, `history.json`, `model_summary.txt`, `best_model.pt`.
Split indices **and file names** are saved in `results/splits/<corpus>_<mode>_seed<seed>.json`.
`scripts/aggregate_results.py` produces `per_run.csv` (all seeds), `summary.csv`, `paired_tests.csv`.
`./reproduce.sh` runs everything.

## Major issue 3 – ablations / component controls
`scripts/ablation.py` runs the full 2³ factorial of {dim, int, phase} on top of CE+focal
(`categorical`, `dim`, `int`, `phase`, `dim_int`, `dim_phase`, `int_phase`, `full`) plus
`full_shuffled_proto` (same losses but prototypes permuted across classes, testing whether the
theory-derived anchors matter). Repeated seeds, both backbones, same config as the main runs.
Paired tests (mean difference, 95 % CI, t-test, Wilcoxon, Holm correction, win/tie/loss) are in
`paired_tests.csv`; pairs are only formed if split/normalisation fingerprints and model/train
config are identical.

## Major issue 4 – architectures and objectives actually used
The record stores the resolved config, `n_parameters`, `model_summary.txt` (full module print)
and `effective_loss_weights` for every run, so the architecture and objective behind each
number can be audited. Results that cannot be regenerated by this pipeline should be excluded
from the main evidence or labelled historical.

## Major issue 5 – matched leave-corpus-out baselines
`scripts/leave_corpus_out.py` trains `categorical` and `full` for both backbones and both
directions with identical source split, normalisation, initialisation, batch order, epochs and
target test set.

## Minor issues
* The aggregator prints the evaluation protocol under every table (`report.md`) and excludes
  records not produced by this pipeline version.
* `report.md` repeats a caution about low-power paired tests with few seeds; with 5 seeds the
  smallest possible two-sided Wilcoxon p is 0.0625, so use `--seeds 42,...,51` for tighter claims.

## Not verified here
The environment used to prepare these changes had no PyTorch, audio data or network access.
The split/normalisation/statistics code and leakage tests were executed (torch-stubbed for the
dataset-view logic); full training runs were **not** executed. Please run `./reproduce.sh`
(or `python scripts/smoke_test.py && python -m pytest tests`) before using any number.
